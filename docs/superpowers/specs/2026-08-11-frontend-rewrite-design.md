# 企业知识助手前端重写设计

## 目标与边界

将现有 Streamlit 单页前端替换为独立的 React + Vite + TypeScript 应用，保留当前 FastAPI 后端和 API 契约。产品同时面向员工与知识管理员，但第一阶段不引入登录或角色权限。

默认入口是问答工作台：员工能立刻提问并核验来源；知识库、历史记录等管理能力独立且随时可达。第一阶段不调整 RAG、Agent 或索引逻辑。

## 信息架构

桌面端使用统一应用壳：左侧导航、主内容区，以及仅在回答含来源时显示的右侧来源速览区。导航包含：

- 问答工作台（默认）
- 知识库
- 历史记录

移动端收起左侧导航为顶部栏与抽屉。来源、推理计划和管理操作均按需展开，避免占据问答主流程。

## 页面与组件边界

`AppShell` 提供导航、服务状态和响应式布局。页面包括：

- `ChatWorkspace`：示例问题、提问输入、流式对话与空状态。
- `AnswerPanel`：按“答案正文、引用来源、推理计划”的顺序展示结果；来源默认可见，推理计划默认折叠。
- `KnowledgeLibrary`：文件上传、上传状态、文档预览、删除和索引概况。
- `HistoryPage`：最近对话、问题复用和清空历史。
- `ApiClient`：唯一封装健康检查、文档管理、历史、同步问答和 SSE 流式问答。

组件不得直接调用网络接口；页面通过数据 hooks 或状态层使用 `ApiClient`，以保证错误策略一致并为后续权限接入留出边界。

## 数据与交互流程

1. 应用启动时读取健康状态、文档概况和必要的页面数据。
2. 用户发送问题后，问题立即进入对话流，前端订阅现有 `/query/stream` SSE 端点。
3. 流中的回答文本逐步写入 `AnswerPanel`；计划与来源在相应事件抵达后更新。完成事件结束生成状态。
4. 用户可在来源区查看标题、文档名、相关片段和得分；推理计划仅按需展开。
5. 文件上传、删除文档、清空历史后刷新对应数据与服务统计。

前端提供中止当前网络请求的能力；这只终止浏览器读取，不改变既有后端接口。

## 视觉系统

以根目录 `DESIGN.md` 的黑白、扁平和高信息密度语言为参考，但不复制 Nike 品牌、专有字体、摄影叙事或电商组件。

- 主界面颜色：`#111111`、`#ffffff`、`#f5f5f5`；绿色仅表示成功/在线，红色仅表示错误、删除和风险操作。
- 使用 8px 间距体系、浅灰表面和 1px 分割线建立层级；不使用渐变、投影或玻璃拟态。
- 主操作使用黑色 48px 高的胶囊按钮；每个可视区域最多一个黑色主操作。次操作为浅灰胶囊或文字操作。
- 回答以白底阅读区呈现；来源片段使用浅灰扁平区域；推理计划使用细线折叠面板。
- 欢迎区使用 40–48px（移动端 30–34px）的强层级标题，长回答正文保持舒适行宽与易读字距。
- 支持手动和系统深色主题。深色使用暖黑背景、低亮度白字及调整后的语义颜色，而不是简单反色。
- 动效只用于流式文本、加载、状态切换和面板展开；遵循减少动态效果偏好。

## 响应式与可访问性

采用移动优先布局：375px 起单列，随后逐步增强为桌面导航与来源旁栏。所有触控目标至少 44px；移动端正文不小于 16px；键盘焦点始终可见且对比度达到 WCAG AA。导航抽屉、来源详情和确认对话框均需可通过键盘关闭和操作。

## 异常与空状态

- 后端断开时，顶部显示明确状态，并为失败请求提供重试，不显示伪造答案或来源。
- 上传显示队列、处理中、成功和单文件失败原因；一个失败不阻塞其他文件。
- 删除文档与清空历史须先二次确认。
- 问答空状态提供示例问题；知识库空状态说明文件支持范围并引导上传；历史空状态引导从问答开始。

## 验收标准

- 流式问答能连续输出、展示引用来源，并将推理计划默认折叠。
- 文档能够上传、查看、删除；历史能够浏览、复用和清空。
- 桌面端与移动端导航、来源区和阅读区在窄屏下不溢出。
- 网络失败、上传失败和空数据均有清晰、可恢复的反馈。
- 核心流程覆盖接口单元测试和端到端测试：流式问答、文档管理、历史记录及移动导航。

## 非目标

- 登录、角色权限和多租户隔离。
- 改造 FastAPI、RAG、Agent、检索或索引策略。
- 复制参考设计中的品牌资产、商业内容或专有字体。
